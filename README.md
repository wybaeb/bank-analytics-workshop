# Рабочая папка практики: инструменты анализа и методы

Семь кейсов банка, четыре инструмента, один стенд. Данные синтетические, ключи
наружу не уходят. Стенд разворачивается двумя способами: локально одной
командой или на общем окружении с VS Code в браузере — см. ниже.

## Как открыть

### На общем стенде (VS Code в браузере)

Если преподаватель прислал ссылку на VS Code в браузере — стенд уже поднят.
Ничего доустанавливать не надо, Docker и Postgres на вашей стороне не нужны.
Подробные шаги — в [`_STAND.md`](_STAND.md). Короткая версия:

1. Открыть VS Code по ссылке, в сайдбаре найти папку `bank_workshop/`.
2. Открыть тетрадь любого кейса, вверху нажать **Restart Kernel** → **Run All**.
3. В Metabase в редакторе SQL выбрать базу «Учебная база банка», а не
   «Sample Database».

### Без git

Если git или сайт репозитория недоступны — та же папка лежит на странице
файлов практики сайта материалов:
<https://wybaeb.github.io/a360/practice_files.html>. Архив целиком и каждый
файл по отдельности, с указанием, что нужно для какого кейса.

### Локально одной командой

Нужен Docker и Python 3.10 или новее.

```bash
pip install -r requirements.txt
cp .env.example .env          # вписать ключ ассистента
./run.sh up
```

Через минуту-две поднимутся два сервиса:

- база: `postgresql://bank_user:bank_pass@localhost:5433/bank_training`
- дашборды: <http://localhost:3000>, вход `workshop@example.local` / `WorkshopBI2026!`

Пароли учебные и действуют только на вашей машине.

Другие команды: `./run.sh status` — что запущено и сколько строк в таблицах,
`./run.sh sql` — консоль к базе, `./run.sh dump` — снять дамп,
`./run.sh reset` — снести стенд вместе с данными и собрать заново.

## Ключ ассистента

Тетради работают с GigaChat. В `.env` нужен `GIGACHAT_AUTH_KEY` — строка
авторизации из личного кабинета. Если под рукой другой ассистент с
OpenAI-совместимым интерфейсом, заполните вместо неё `AI_PROVIDER_URL` и
`AI_PROVIDER_TOKEN` и добавьте `ASSISTANT_BACKEND=openai` — тетради работают
одинаково через оба пути.

Провайдер должен уметь новый OpenAI-протокол `tools`/`tool_choice`: агентские
тетради без него отвечают текстом «Tool use: …» вместо реальных вызовов.
На общем стенде ключ и провайдер уже настроены преподавателем.

Файл `.env` в репозиторий не попадает — так ключ и остаётся у вас.

## Что где лежит

```
data/            выгрузки в CSV и генератор, который их создаёт
sql/init/        схема, загрузка данных и представления портфеля
sql/dump/        полный дамп базы — если удобнее поднять без docker
tools/           клиент ассистента, SQL в ячейках тетради, два агента, проверки
2.N_*/, 3.N_*/   сами кейсы: промпты, тетради, эталоны, разборы
```

Данные создаются скриптами с фиксированным зерном: `python3 data/generate_data.py`
для кейсов стенда и `python3 data/generate_data_step3.py` для наборов
`product/`, `clients/` и `series/` — повторный запуск всегда даёт те же файлы,
поэтому числа в материалах не разъезжаются.

Кейсы 3.3 и 3.4 базу не используют: тетради читают выгрузки прямо из `data/`.
Сверх общих библиотек им нужны `scikit-learn` и `plotly` — они в
`requirements.txt`.

## Что можно проверить, ничего не запуская

```bash
python3 tools/check_env.py          # что подключено, чего не хватает (без вывода ключей)
node tools/check_apps_script.js     # эталонный скрипт для таблиц даёт ожидаемые числа
./run.sh status                     # в базе ровно столько строк, сколько должно быть
```

На общем стенде вместо `./run.sh status` пересчёт делается запросом:

```bash
psql -h postgres -U bank_user -d bank_training \
  -c "SELECT 'raw_applications', COUNT(*) FROM raw_applications"
```
