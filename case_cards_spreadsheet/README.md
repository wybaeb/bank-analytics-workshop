# Карточный бизнес: таблица, ассистент и скрипт

**Управленческий вопрос.** Карты выдаём, а покупок в первый месяц нет. Где именно
теряется активация и что делать с этим каналом?

Показываем путь целиком: сырая выгрузка → просим ассистента написать скрипт →
выполняем скрипт → получаем сводную и диаграмму прямо в таблице.

## Что в папке

| Файл | Зачем |
|---|---|
| `data/cards_issued_raw.csv` | выгрузка для Google Таблиц (импорт файлом) |
| `data/Выгрузка_по_картам.xlsx` | та же выгрузка для Excel, лист «Выгрузка» |
| `промпт_для_ассистента.txt` | текст, который вставляем в ассистента на занятии |
| `reference/активация_карт.gs` | рабочий скрипт для Google Таблиц |
| `reference/активация_карт.bas` | тот же алгоритм макросом для Excel |
| `разбор_ответа_ассистента.md` | что ассистент сделал не так и как это заметить |

## Что не так с выгрузкой

Всё как в жизни: повторы строк после склейки файлов, даты в двух форматах и «н/д»,
суммы то с пробелом-разделителем, то с запятой, а канал оформления записан
тринадцатью разными способами — «Отделение», «отделение», «ОТДЕЛЕНИЕ », «Офис банка»,
«МП», «Партнер»… Пока это не приведено к четырём значениям, любая группировка по
каналу даёт бессмысленную таблицу на тринадцать строк.

## Как провести

**1. Импорт.** Google Таблицы → «Файл → Импортировать → Загрузить» →
`cards_issued_raw.csv`, разделитель — точка с запятой. Лист назвать «Выгрузка».
Покажите вкладку: 2472 строки, канал написан вразнобой.

**2. Запрос к ассистенту.** Вставьте текст из `промпт_для_ассистента.txt`.
Ассистент выдаёт скрипт за полминуты.

**3. Приёмка кода — главная часть.** Прежде чем запускать, проверьте скрипт по
списку из `разбор_ответа_ассистента.md`: там ровно те ошибки, которые ассистент
делает на этой задаче. Найти их в чужом коде за минуту — это и есть навык.

**4. Выполнение.** «Расширения → Apps Script», вставить проверенный скрипт,
запустить `obrabotatVygruzku`. Если времени мало — вставляйте сразу
`reference/активация_карт.gs`, он проверен.

**5. Результат.** На листе «Выгрузка» — 2400 строк, чистые даты и числа, новый
столбец активации. На листе «Активация» — две сводные таблицы и диаграмма.

## Что должно получиться

После чистки остаётся **2400 строк** из 2472.

| Канал оформления | Карт | Активировано | Доля активации |
|---|---:|---:|---:|
| Мобильное приложение | 813 | 625 | **76,9 %** |
| Отделение | 768 | 489 | 63,7 % |
| Сайт банка | 386 | 231 | 59,8 % |
| Партнёрская сеть | 433 | 164 | **37,9 %** |

| Тарифный план | Карт | Активировано | Доля активации |
|---|---:|---:|---:|
| Зарплатный | 673 | 484 | 71,9 % |
| Премиальный | 322 | 217 | 67,4 % |
| Классический | 1036 | 609 | 58,8 % |
| Кэшбэк-максимум | 369 | 199 | 53,9 % |

Вывод, который виден без всяких моделей: партнёрская сеть даёт вдвое меньшую
активацию, чем мобильное приложение. Разговор дальше идёт не про «поднять
активацию вообще», а про один канал и то, что происходит с клиентом сразу после
оформления карты.

## Проверка

Логика эталонного скрипта прогоняется на той же выгрузке вне таблиц:

```bash
node tools/check_apps_script.js
```

Скрипт сверяет число строк после чистки, разбор дат и сумм, приведение каналов и
все восемь чисел из таблиц выше.
