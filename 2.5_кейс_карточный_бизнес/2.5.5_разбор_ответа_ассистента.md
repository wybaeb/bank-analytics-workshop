# Что ассистент сделал не так

Ниже — разбор настоящих ответов на промпт из этой папки. Скрипт каждый раз
выглядит убедительно: русские комментарии, аккуратные функции, готовый результат.
Запускать его без проверки нельзя — вот что находится за минуту чтения.

Ошибки отсортированы по цене: сверху те, что молча портят число, в которое потом
верят.

## Тихие ошибки — расчёт проходит, результат неверный

**Повторы не удаляются.** Ассистент сравнивает уже преобразованную строку с исходной:

```javascript
if (!isRowDuplicate(row, processedData)) {   // processedData — уже нормализованные строки
```

Совпадений не будет никогда, потому что в `processedData` канал уже приведён к
четырём значениям, а в `row` он ещё не преобразован. Дубли остаются, все доли считаются по
2472 строкам вместо 2400.
*Как заметить:* после запуска сравните число строк — оно не изменилось.

**Всё неизвестное молча попадает в один канал.**

```javascript
default: return 'Партнёрская сеть';   // всё остальное считаем партнёрской сетью
```

Любая опечатка, новый канал, пустая ячейка — всё это увеличит именно ту группу,
по которой делается управленческий вывод. Ошибка не видна: таблица выглядит
правильно, в ней ровно четыре строки.
*Как чинить:* неизвестные значения складывать в отдельную группу «Прочее» и
смотреть, сколько их.

**Половина дат разбирается неправильно.**

```javascript
const parts = dateStr.split(/[\.\-\/]/);
return new Date(parts[2], parts[1] - 1, parts[0]);
```

Для «15.03.2025» это верно, а для «2025-03-15» даёт `new Date(15, 2, 2025)` —
пятнадцатый год. Признак активации по таким строкам считается от несуществующей
даты.
*Как заметить:* отсортируйте столбец с датой выдачи по возрастанию — сверху
окажутся даты начала прошлого века.

**Дробная часть превращается в тысячи.** В первом варианте ответа:

```javascript
const numVal = parseFloat(cellValue.replace(/\s|,/g, ''));
```

Запятая удаляется вместе с пробелом, и «12000,50» становится числом 1 200 050.
Оборот по такой карте вырастает в сто раз.

## Ошибки, которые видно сразу

**Путаница нумерации.** Функция поиска столбца возвращает индекс массива
(с нуля), а результат подставляется и в массив, и в `getRange`, где нумерация
идёт с единицы:

```javascript
function getColIndex(sheet, columnName) { return ...findIndex(...); }   // 0, 1, 2…
sheet.getRange(i, getColIndex(sheet, 'Дата выдачи')).getValue();        // ждёт 1, 2, 3…
```

Скрипт читает соседний столбец или падает на нулевом индексе.

**Скрипт не успеет доработать.** Обращение к ячейкам по одной внутри цикла на
2500 строк — это тысячи обращений к таблице, а у Apps Script есть предел времени
выполнения. Данные читают одним `getValues()` и пишут одним `setValues()`.

**Вызов несуществующего метода.** `resultSheet.newPivotTableBuilder()` в Apps
Script нет — сводную таблицу создают от диапазона. Эта ошибка честная: скрипт
просто не запустится.

## Что из этого следует

Ассистент экономит час написания кода и не экономит ни минуты приёмки. Приёмка —
это три вопроса к любому сгенерированному скрипту:

1. Изменилось ли число строк там, где оно должно было измениться?
2. Куда делось то, что скрипт не смог разобрать: в отдельную группу или тихо
   в одну из существующих?
3. Совпадает ли контрольная цифра, которую можно посчитать вручную на десяти
   строках?

Проверенный вариант скрипта лежит рядом: `2.5.6_эталон_google_apps_script.gs`.
